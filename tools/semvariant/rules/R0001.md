# Apply relevant semvariant rules before editing or reviewing a change.

Halo is an open-source self-modifiable desktop app built with Electron and Pi. It is a work in progress and has not been publicly launched.

Rule files in `tools/semvariant/rules/` are the source of truth for repository guidance. Their `guides` lists assign titles to directory-scoped `AGENTS.md` files. Rules apply in the listed directory and its descendants, together with rules from ancestors. A title is an index entry; read the full rule before applying it or judging a violation.

Use `pnpm semvariant context <paths>` for explicit paths, `pnpm semvariant context --staged` for the index, or `pnpm semvariant context --diff <rev>` for changes against a commit. Add `--full` to include bodies. `pnpm semvariant show R0001` retrieves a rule by ID; `pnpm semvariant search <terms>` searches bodies and titles. Read the relevant rules, not every body for every task. The semvariant skill at `.agents/skills/semvariant/SKILL.md` describes the editing workflow.

Apply guidance to the changed area without turning a focused task into a full migration. Keep current architecture and migration progress in the implementation spec, update it as work lands, and do not describe planned APIs as available. Examples are simplified TypeScript adapted from real code, not complete implementations; imports and unrelated setup may be omitted.
