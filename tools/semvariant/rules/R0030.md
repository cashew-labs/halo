# Construct shared dependencies at their lowest common lifetime owner.

A composed service owns its children. Place a shared child at the lowest common owner that needs it. For example, threads and tools share a database and its transaction coordination:

```ts
// Avoid: separate connections to the same file.
const threads = new ThreadRepo({
  database: new DatabaseClient({ path: databasePath }),
});
const tools = new ToolRuntime({
  database: new DatabaseClient({ path: databasePath }),
});
```

Instead, have the host open the database once and supply it to the server. The server passes that capability to its children:

```ts
// Prefer: both children borrow the database supplied by the host.
const database = host.database;
const threads = new ThreadRepo({ database });
const tools = new ToolRuntime({ database });
```

The host opens the database before starting the server and closes it after the server stops its consumers. The server owns its internal children; they borrow the host-supplied database. Place host-owned resources at the lowest common host lifetime that needs them. Sharing is not a reason to move the database into a process-global singleton.

Use a constructor for synchronous setup and `start()` or `create()` for fallible asynchronous setup. Construct children in dependency order and register cleanup as resources are acquired, including for failed startup. `using` or `await using` with disposable stacks keeps reverse-order cleanup together with acquisition.
