# Keep apps as thin hosts for independently testable service packages.

Use pnpm workspaces and Turborepo. Name workspace packages with the `@get-halo/*` scope. Keep deployable hosts in `apps/`, reusable services and UI in `packages/`, and deployment configuration in `infra/`.

Each app's service behavior belongs in a corresponding package behind a supported public API. This includes business logic and shared UI behavior. Apps supply configuration and concrete effectful dependencies, compose the packages, and own process startup and shutdown. Keep product decisions and service state transitions in the owning package rather than the host's wiring or adapters.

The package must be constructible and testable without importing app internals or launching the deployable app. Multiple apps may host the same package; corresponding does not require matching names or a separate package for each host. Reusable packages do not import app internals. Keep dependencies acyclic.
