# Have hosts supply concrete effectful dependencies through narrow service-owned interfaces.

Define narrow, service-owned interfaces for effectful dependencies, including filesystem, database, network, inference, and platform access. Hosts select, construct, and supply the concrete implementations, even when there is currently only one host. Reusable services perform effects through those supplied capabilities rather than selecting concrete environment adapters internally.

Packages still own business behavior and compose their internal services. Share a service when behavior above an interface needs state; do not mirror every third-party API or wrap deterministic helpers. The boundary exists to run the same behavior with capabilities supplied by production, development, or a test fixture.

The host owns its private bridges. Callers supply configuration, not the IPC or browser bridge that the host should construct. Importing a reusable package must not read deployment configuration, touch disk, or start services.

Keep local worries local. Do not compensate in one place for unrelated behavior owned somewhere else; identify the ownership boundary and fix the design there.
