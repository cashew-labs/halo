# Keep rules as guidance, skills as procedures, and implementation facts at their source.

Rules express repository facts, constraints, and criteria for judgment. Skills describe reusable workflows and tool operation. Link between them when needed, rather than duplicating policy in skills.

Reference implementation sources for changing inventories, commands, schemas, versions, and architecture. Keep operational detail when it is needed to apply a rule, but avoid copying catalogs that will drift. Implementation specs describe current architecture and migration progress; rule titles must not present planned behavior as shipped.
