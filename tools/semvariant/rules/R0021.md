# Verify Entire retrieval and sync with live evidence rather than status alone.

Run `node .agents/entire.mjs` for fast startup diagnostics. It tests offline capture and plugin versions and shows the last worker receipt with its timestamp; that receipt is not a live check. Run `node .agents/entire.mjs --remote` after committing and pushing to check a readable stored transcript, the exact private remote ref, absence from public origin, hosted search results, and local Graph/Brain queries. Remote diagnostics exit nonzero unless every required proof is verified; the historical worker receipt is not a required live proof. Retrieval must match the latest captured user request, the exact checkpoint source path, and the exchange range containing that request and reaching into the checkpoint's new transcript window. A tool-only continuation can verify the continuing exchange, but not claim a new user turn; a transcript without searchable user text cannot prove conversation retrieval. Brain 0.4 can reuse exchange IDs across cumulative checkpoint copies, so expand the returned `session_ref` for branch/session navigation and verify evidence against the stored transcript instead of assuming `get <conversation-id>` selected the newest copy. A session reference alone does not identify a unique checkpoint. A binary, hook, trailer, empty search response, or saved connection alone does not prove retrieval or sync works. Parser limitations are reported separately from source-code failures.
