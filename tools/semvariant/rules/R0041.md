# Test service behavior independently through package APIs and host wiring through app surfaces.

Test service business logic and shared UI behavior independently through the owning package's main supported exports. A package fixture constructs the same service or mounts the same UI with explicit capabilities; it must not import app internals or launch an app entrypoint. These tests must establish the package's behavior without relying on app-level coverage.

App tests exercise host integration through the app's public UI or protocol. They complement package tests by checking concrete wiring and platform behavior. The consumer boundary defines E2E, not the number of processes: an exported reducer can be tested directly. Use Vitest for library/server APIs and Playwright for UI workflows.

Independent package testing does not require mocked internal services. Use real local dependencies and control unavailable external systems at the host boundary as described in R0043.

For an exported reducer, that means testing `applyThreadEvent(emptyThreadSnapshot(), event)` through the client package's root export. Do not start a server just to call it, or import a private module and relabel the test as a package E2E.
